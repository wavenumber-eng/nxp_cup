THE FOREGROUND LOOP

Follow one accepted camera frame

The framework keeps only the newest pending frame.

  1. 01Camera completes RGB565 frameproducer marks the latest buffer ready
  2. 02nxpc_framework__service()inputs, mode, safety, USB, display
  3. 03nxpc_framework__take_latest_frame()returns a fresh frame or NULL
  4. 04switch on current modeTEST / RACE RUNNING / no callback
  5. 05time the selected callback41 ms budget; three overruns fault
  6. 06nxpc_framework__finish_frame(frame)publish bounded presentation, then release
Why no queue?

If a new frame arrives before an older pending frame is accepted, the older one is replaced and the drop counter rises. Latency stays bounded: student code works from the newest view, not an increasingly stale backlog.

See the real main.c dispatch 
while (1) {
    nxpc_framework__service();
    frame = nxpc_framework__take_latest_frame();
    if (frame == NULL) continue;

    switch (nxpc_system__mode()) {
    case NXPC_SYSTEM_MODE_TEST:
        nxpc_framework__begin_callback();
        test_mode_on_frame(frame);
        nxpc_framework__end_callback();
        break;
    case NXPC_SYSTEM_MODE_RACE_RUNNING:
        nxpc_framework__begin_callback();
        race_mode_on_frame(frame);
        nxpc_framework__end_callback();
        break;
    default:
        nxpc_framework__no_callback();
        break;
    }
    nxpc_framework__finish_frame(frame);
}

    03 · CALLBACK CONTRACT

    Borrow the frame. Finish one pass. Return.

    uint16_t *frame is writable RGB565.

    app/race_mode.cstudent-owned
    void race_mode_on_frame(uint16_t *frame)
{
    // 1. Choose rows with camera_row().
    // 2. Inspect pixels / convert color.
    // 3. Make your bounded decision.
    // 4. Command steering and motors.
    // 5. Publish useful telemetry.

    // Then return promptly.
}
    DO

    Read pixels, convert colors, draw temporary overlays, call the public API, and return within the frame budget.

    DO NOT

    Keep the frame pointer, free it, hand it to asynchronous work, include private drivers, or wait forever.

    41 ms

    is the callback budget. Three consecutive overruns enter SAFE_FAULT.

    100 ms

    is the motor command lease. Each accepted motors_set_duty() refreshes it.

    04 · DAILY WORKFLOW

    Edit, build, flash, observe.

    Run commands from the repository root in PowerShell.

    1. 01
      Editsrc\embedded\nxp_cup_core0\source\app\vision_test.c...\app\race_mode.c

      Additional top-level app/*.c files are discovered automatically.

    2. 02
      Build.\src\embedded\build.ps1

      The normal Rev A competition image is emitted under out\artifacts\embedded.

    3. 03
      Flash.\src\embedded\flash.ps1

      ROM-HID through J11 is tried first; J-Link Commander is the fallback.

    4. 04
      Observe.\out\artifacts\host\nxpc_viewer.exe

      Use overlays, named telemetry, logs, callback time, and frame drops.

    Before motion: lift the driven wheels or disconnect motor power. TEST MOTORS still requires deliberate arming; RACE starts only after a live frame and EXE release.

    When adding code: include your own header and nxp_cup.h. Do not add a second build or flash path.

    KEEP THIS MODEL

    A fresh frame enters the foreground. The mode chooses one callback. Your callback borrows the frame and requests outputs. The framework times, presents, and safely releases everything.
