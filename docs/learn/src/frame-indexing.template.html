NXP CUP · VISION · 04 PIXEL (x, y) → ARRAY INDEX → MEMORY

From camera image to C array

A frame looks two-dimensional.
Memory is one long row.

The NXP Cup camera gives your callback a flat uint16_t * containing a 320 × 200 image. Every RGB565 pixel occupies one array element. Rows are stored left-to-right, then top-to-bottom.

03 · REAL CAMERA CALCULATOR

Now use width = 320

The firmware constants are CAMERA_WIDTH = 320, CAMERA_HEIGHT = 200, and CAMERA_STRIDE_PIXELS = 320.

ELEMENT INDEX27,017 84 * 320 + 137
BYTE OFFSET54,034 index * sizeof(uint16_t)

DIRECT FLAT INDEX

uint16_t pixel =
    frame[y * CAMERA_STRIDE_PIXELS + x];

Useful when you need one coordinate and want the layout to be explicit.

=

ROW HELPER

uint16_t *row = camera_row(frame, y);
uint16_t pixel = row[x];

Usually clearer when scanning several pixels from the same row.

Bounds are your responsibility. camera_row(frame, y) does not clip. Use x < CAMERA_WIDTH and y < CAMERA_HEIGHT before reading.

FRAME LIFETIME

Borrow it. Use it. Return.

callback begins→read or draw pixels→callback returns→pointer is no longer yours

The frame is writable RGB565 and valid only until the callback returns. Do not retain the pointer, free it, or hand it to asynchronous work.
