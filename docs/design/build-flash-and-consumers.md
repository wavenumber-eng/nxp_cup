# Build, Flash, and Consumer Layout

## Repository contract

The repository root owns one Windows bootstrap, shared configuration, plans,
tests, and documentation. Each buildable component owns its source, build entry
point, detailed README, and local tools:

| Component | Build command | Published artifacts |
| --- | --- | --- |
| MCXN947 firmware | `.\src\embedded\build.ps1` | `out/artifacts/embedded` |
| Native viewer and CLI | `.\src\host\build.ps1` | `out/artifacts/host` |
| Android relay | `.\src\android\build.ps1` | `out/artifacts/android/nxp_cup_bridge.apk` |

Repository-owned tools, intermediate builds, test results, and distributable
artifacts stay below the ignored `out` directory. Conventional component caches
such as Gradle, npm, and pytest state remain ignored in their normal locations.

## Firmware

Provision once, then build the single normal competition image:

```powershell
.\setup.ps1
.\src\embedded\build.ps1
.\src\embedded\build.ps1 -Clean
```

The wrapper runs the `competition` presets from `src/embedded`, publishes AXF
and BIN copies, and leaves the authoritative CMake output at
`out/build/embedded/competition`. The preset is Rev A: EZH camera capture,
ER-TFT020-3 SPI LCD, session-gated USB telemetry, and QDC wheel feedback.

The MCUXpresso project remains at `src/embedded/nxp_cup_core0`. Source-list
drift and fresh headless IDE comparisons are maintainer checks under
`src/embedded/tools/maintainer`; obsolete one-off diagnostic wrappers are not
part of the supported structure.

## Host

`src/host/build.ps1` uses LLVM-MinGW/Clang explicitly by default. MSVC is an
optional explicit comparison using `-Toolchain MSVC`; there is no automatic
compiler selection. The native CLI/viewer, browser viewer, packaging script,
and Playwright tests all live under `src/host`.

The WebSerial and Android relay bundles are generated by `src/web/build.ps1` from shared
Formula One presentation sources and consumer-owned transport adapters. The committed
outputs are the standalone host page and Android's `res/raw/relay_viewer.html`; both are
dependency-free at runtime and checked for source/output drift. The host wrapper delegates
to that single bundler. The generated Formula One relay page is Android's sole HTML
resource; the superseded legacy presentation is not retained. See
`docs/design/shared-web-dashboard.md`.

## Android

Android licenses remain an explicit component-specific operation:

```powershell
.\src\android\setup.ps1 -AcceptLicenses
.\src\android\build.ps1
.\src\android\build.ps1 -Offline
```

Pinned JDK, SDK, ADB, and Gradle tools normally live under
`out/toolchains/android`. A parallel worktree may set `NXPC_ANDROID_TOOLS_DIR`
to reuse that provisioned directory without duplicating downloads.

The proven `nxp_cup_bridge` app currently owns native preview and relay behavior in one
application. Any later viewer-only/relay module split must reuse a shared Kotlin core and
follow the Android plan rather than cloning protocol, USB, or frame code.

## Flash workflow

`src/embedded/flash.ps1` first tries the ROM-HID backend and falls back to
command-line J-Link Commander when ROM flashing is unavailable. Passing
`-Backend Rom` or `-Backend JLink` disables fallback and forces that path. The
companion RTT command is maintainer tooling rather than part of student setup.

## Compatibility

Moving consumers did not change protocol version 1, `AVCU` wire magic
`0x55435641`, runtime USB `1FC9:0094`, ROM HID `1FC9:014F`, packed message
values, or H.264 `video/avc` identifiers.
