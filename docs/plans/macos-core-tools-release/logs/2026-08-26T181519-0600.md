# Guarded multi-platform release flow

Extended the existing host release entry point to select the native platform explicitly
or automatically. Windows retains its `core-tools-v<version>` tag, x64 asset name,
schema-1 flat payload, release title, and validation path. Apple Silicon uses the separate
`core-tools-macos-v<version>` tag and arm64 asset established by the frozen contract; the
script refuses cross-host release builds.

The Mac archive validator now extracts with native ZIP mode preservation, verifies the
outer checksum, exact recursive payload and manifest coverage, every size and SHA-256,
schema-2 metadata, app identity/version, minimum macOS 13, thin arm64 Mach-O payloads,
executable modes, system-only dynamic dependencies, all individual signatures, the deep
app signature, and the packaged CLI self-test. Publication additionally requires a
Developer ID Application identity, an external Keychain notary profile, accepted Apple
notarization, a stapled ticket, and Gatekeeper acceptance. Ad-hoc dry runs cannot claim
notarization or enter publication.

The package entry point now supports the guarded publication sequence: secure-timestamp
Developer ID signing, a bounded 30-minute `notarytool` submission, accepted-result
parsing, app ticket stapling/validation, Gatekeeper assessment, manifest recording, and
final archive generation. Credential data remains outside the repository. No signing or
notary service was invoked in this dirty-tree dry run.

The complete `release.ps1 -Version 0.1.0 -Platform MacOS -AllowDirty -Force` dry run
passed native build and self-test, deterministic dashboard checks, learning-page checks,
all 15 Playwright browser tests, packaging, extraction, and the complete Mac archive
validator. It selected `core-tools-macos-v0.1.0` and performed no upload. Negative checks
also proved wrong-host release, missing notary profile, and ad-hoc notarization are
rejected before mutation.

The browser test launcher now selects `powershell.exe` on Windows and `pwsh` elsewhere.
The shared dashboard generator uses the host newline convention, preserving the existing
Windows behavior while making its two committed outputs byte-stable on macOS.
